# MSI v0.7.0 — Timeline and user-scheduled local scans

## Scope
Build v0.7.0 on top of the v0.6.0 product-suite branch without changing `main`, merging PR6, or publishing a release.

## Product behavior
- Add a local event timeline derived only from differences between consecutive user-triggered or explicitly scheduled scans.
- Establish a local baseline on the first scan. Do not infer an install/uninstall solely from a package list difference; phrase it as appeared / no longer visible.
- Track app version changes, signature changes only when both SHA-256 fingerprints are known, granted sensitive-permission additions/removals, active special-access changes, and observed VPN state changes.
- Persist timeline events locally, cap the timeline at 500 events, and clear it together with scan history only after explicit user confirmation.
- Show a daily summary of recorded events; this is a count of observations, not a risk score or malware verdict.
- Let the user select the local daily scan time. Scheduled scanning remains disabled by default and can be cancelled by opting out.
- Explain that WorkManager and Android power policies may delay execution; the selected time is not a minute-accurate guarantee.

## Privacy and security invariants
- No INTERNET permission, network client, analytics, or tracking.
- No uploads or remote profile. All snapshots and events remain in app-private local storage.
- No automatic changes to another app's permissions or settings.
- Unknown package/signature data stays unknown and is excluded from confirmed-change events.
- Notifications remain opt-in and are requested only after the user enables scheduled scans.
- No malware/safety verdicts, no Terminal/shell/Termux/PRoot.
